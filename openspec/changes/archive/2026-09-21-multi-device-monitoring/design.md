# Design

## Context

见 proposal.md - Why。当前 `wifi_speed_monitor.py` 是单设备循环：配置一个 `target_mac`，每轮 `get_device_speed()` 内部拉一次 `device_list` 再筛出单个 MAC，主循环用**一个** `alert_state` 变量做阈值状态机。上传记录格式为 `{ts, download, upload}`。

约束：
- 阈值远程覆盖（`api-settings-sync`）只认一个全局 `download_threshold_mbps`，因此多设备必须共享同一阈值，避免与远程 settings 冲突。
- 设备名已在路由器 `device_list` 返回，无需在配置重复。
- Cloudflare Worker / D1 数据模型将由用户在外部同步修改，脚本只负责按约定产出 `device` 字段。

## Goals / Non-Goals

**Goals:**
- 一次轮询获取全部目标设备速度；每设备独立告警状态机
- 配置由单个 `target_mac` 迁移为 `target_macs` 列表
- 上传记录带稳定的设备标识（字母）

**Non-Goals:**
- 每设备独立阈值（保持全局，见 Decision 1）
- 在配置中维护设备名（取自路由器）
- 修改 Worker/D1 侧实现（用户负责）
- 上传记录携带路由器设备名（只带字母标识）

## Decisions

### 1. 全局共享阈值

**选择**: 所有设备使用同一个 `download_threshold_mbps`。

**备选**: 每设备独立 `threshold_mbps`。

**理由**: `api-settings-sync` 的远程设置接口只覆盖单个阈值；若引入每设备阈值，需要扩展 Worker settings 模型并定义"远程值 vs 本地值"的优先级，复杂度和跨端改动都显著上升。全局阈值下远程覆盖逻辑完全不变。

### 2. 每轮一次 device_list，内存过滤

**选择**: 主循环每轮调用一次 `device_list`，然后在内存中按 `target_macs` 过滤出全部在线目标设备，返回 `(mac, speed, name)` 列表。

**备选**: 对每个 MAC 分别调用 `get_device_speed`。

**理由**: 现方案每轮只发一次路由器请求，设备数增加不增加请求数；过滤是纯内存操作。需要把 `get_device_speed` 重构为面向多设备的形式。

### 3. 设备标识为列表顺序字母

**选择**: 在配置加载时按 `target_macs` 的索引生成 `mac -> "A"/"B"/...` 映射，上传记录写入该字母。

**备选**: 用 MAC 本身、或用字母+路由器名字组合。

**理由**: 用户明确只需两个设备、只要字母，简单直观。**代价**：字母与列表顺序绑定，顺序变化会导致历史数据标识漂移。D1 侧的历史数据需在顺序稳定期间解读。

### 4. 离线设备跳过

**选择**: 目标 MAC 不在 `device_list` 中时，本轮直接跳过该设备：不记速度、不写记录、不评估告警、不改变其告警状态。

**备选**: 照旧记一条速度 0（现有单设备行为）。

**理由**: 避免设备长时间离线时向 D1 灌入大量 0 值污染曲线。状态保留意味着设备恢复后若仍在阈值上不会重复推送，符合"状态只在真实回落时才重置"的语义。

### 5. mock 模式每台返回同一速度

**选择**: mock 时对所有目标设备返回相同的固定速度（沿用 `MOCK_SPEED_BPS`），设备名用占位名。

**理由**: 保持本地可离线验证多设备循环与状态机，不引入额外 mock 配置。若需要区分，可在后续迭代扩展。

### 6. 配置直接切换，不做兼容

**选择**: 删除 `target_mac`，改用 `target_macs` 列表；`load_config` 校验其为非空列表，否则报错退出。

**理由**: 个人项目、配置项少，兼容双写法只会增加分支。本地 `config.yaml` 手动改一次即可。

## Risks / Trade-offs

| 风险 | 缓解 |
|------|------|
| 字母随列表顺序漂移，历史数据标识错位 | 保持 `target_macs` 顺序稳定；已在 spec/README 说明字母来源 |
| Worker/D1 未及时支持 `device` 字段，导致上传被拒或字段丢失 | 脚本与 Worker 需协同发布；`device` 为新增字段，旧 Worker 若忽略未知字段则向后兼容，若严格校验则需同步更新 |
| 每轮产生 N 条记录，`batch_size` 更快触发上传 | 语义不变（按记录数）；60 条在 2 台设备下约 30 轮（~7.5 分钟 @15s），可接受 |
| 配置为空的边界 | `load_config` 显式校验非空列表并报错 |
