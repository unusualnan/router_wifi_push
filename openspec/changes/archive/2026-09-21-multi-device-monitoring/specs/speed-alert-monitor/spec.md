## ADDED Requirements

### Requirement: 多目标设备配置

系统 SHALL 从配置文件的 `target_macs` 列表读取所有要监控的目标 MAC 地址，并按列表顺序为每台设备分配一个字母标识（A、B、...）。

#### Scenario: 配置多个目标设备

- **WHEN** 配置文件包含 `target_macs: ["mac1", "mac2"]`
- **THEN** 系统监控这两台设备，分别对应字母标识 "A" 和 "B"

#### Scenario: 设备名取自路由器

- **WHEN** 系统从设备列表匹配到目标设备
- **THEN** 告警与展示使用路由器返回的设备名，无需在配置中提供设备名

#### Scenario: 配置为空

- **WHEN** `target_macs` 缺失或为空列表
- **THEN** 系统启动时报错并退出

## MODIFIED Requirements

### Requirement: 定时轮询设备速度

系统 SHALL 以可配置的间隔（默认 5 秒）定时调用路由器 API，一次获取配置中所有目标设备的瞬时下行速度。

#### Scenario: 正常轮询

- **WHEN** 轮询间隔到达
- **THEN** 系统调用路由器 API 获取设备列表，并过滤出配置中所有在线的目标设备及其当前下行速度

#### Scenario: 轮询失败

- **WHEN** 路由器 API 请求失败
- **THEN** 系统记录错误日志并在下个轮询周期重试

#### Scenario: 目标设备离线

- **WHEN** 某个目标 MAC 不在设备列表中
- **THEN** 系统跳过该设备：不获取速度、不记录、不告警，且不改变其告警状态

### Requirement: 状态机告警逻辑

系统 SHALL 为每台目标设备独立维护两状态状态机（正常/告警中），仅在状态变化时触发推送。

#### Scenario: 速度从正常变为超过阈值

- **WHEN** 某设备当前状态为「正常」且下行速度超过阈值
- **THEN** 系统将该设备状态切换为「告警中」并发送一次推送

#### Scenario: 告警中速度持续超过阈值

- **WHEN** 某设备当前状态为「告警中」且下行速度仍超过阈值
- **THEN** 系统不发送推送

#### Scenario: 速度从超过阈值回落到正常

- **WHEN** 某设备当前状态为「告警中」且下行速度低于阈值
- **THEN** 系统将该设备状态切换为「正常」

#### Scenario: 速度再次超过阈值

- **WHEN** 某设备当前状态为「正常」且下行速度超过阈值（之前已回落过）
- **THEN** 系统将该设备状态切换为「告警中」并再次发送推送

#### Scenario: 设备离线不改变状态

- **WHEN** 某设备在轮询中离线被跳过
- **THEN** 该设备的告警状态保持不变

### Requirement: 通知内容格式

推送通知 SHALL 包含设备名称、当前下行速度和阈值信息。

#### Scenario: 正常推送

- **WHEN** 触发告警推送
- **THEN** 标题包含设备名，正文包含设备名称、当前速度（MB/s）和阈值（MB/s）
