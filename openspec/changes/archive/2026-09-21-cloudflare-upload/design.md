## Context

现有脚本每次轮询获取速度后只做阈值告警，数据用完即丢。需要增加持久化上传能力，与原有告警逻辑并行。

## Goals / Non-Goals

**Goals:**
- 采集数据缓存到内存，批量上传到 Cloudflare Worker
- 上传失败时保留数据，下次重试
- 通过配置项控制开关和参数

**Non-Goals:**
- 不做本地文件缓存（重启脚本数据丢失可接受）
- 不做上行速度采集（upload 固定 0）
- 不做数据压缩或加密
- 不做 Worker 端的实现

## Decisions

### 1. 内存缓存而非文件缓存

**选择**: 用 Python list 在内存中缓存记录

**备选方案**: 写入本地 JSON 文件或 SQLite

**理由**: 脚本是短生命周期进程（重启即丢数据可接受），内存缓存最简单。文件缓存增加复杂度但收益不大。

### 2. 双触发条件

**选择**: batch_size 或 upload_interval 任一满足即上传

**理由**: batch_size 防止数据量过大导致请求超时；upload_interval 保证低流量时数据也能及时上传。

### 3. 上传失败不清空

**选择**: 上传失败时保留全部缓存，下次重试时合并上传

**备选方案**: 丢弃失败数据 / 只保留最新 batch_size 条

**理由**: 用户要求失败重试。最简单的方式是不清空，下次自然重试。风险是如果 Worker 长期不可用，缓存会持续增长，但脚本重启即可清空。

## Risks / Trade-offs

| 风险 | 缓解措施 |
|------|---------|
| Worker 长期不可用导致缓存膨胀 | 脚本重启清空；可加个上限（如 1000 条）丢弃最旧记录 |
| 上传请求耗时影响轮询间隔 | 上传放在独立 try 中，不阻塞主循环 |
| 时间戳精度 | 使用 ISO 8601 UTC 格式，秒级精度足够 |
